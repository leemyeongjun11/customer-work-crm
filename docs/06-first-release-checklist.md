# 첫 배포까지의 고정 작업 목록

6차 진행 요청에 따라 범위를 계속 늘리지 않고 아래 여섯 묶음을 기준으로 진행한다. **현재 6.1 MVP 구축 중**이며 완료율을 임의의 퍼센트로 표시하지 않는다. 묶음 안의 세부 구현·검수는 별도 기록한다.

| 묶음 | 완료 기준 | 현재 남은 일 |
|---|---|---|
| 1. 문의 접수·연동 | 원문 보존, 중복 방지, 담당자·기한 배정, 열린 화면 자동 반영, 누락 복구 | 자체 접수·서명 수신·실시간 갱신·보충 처리 엔진·HTTPS 조회 어댑터·60초 예약 연결 구현. Emergent 실제 주소·인증·폼 매핑·발신 전송기와 실제 지연 측정 남음 |
| 2. 알림 | 실제 접수 확인·담당자·기한 알림 수신 및 실패 처리 검증 | 로컬 예약·처리·중복/실패 검사 구현. 메일 제공자·발신 주소·검수 수신함 연결 및 실제 발송 검수 남음 |
| 3. AI | 영업 기록·다음 행동의 근거 있는 제안/반영, 종료·담당자 변경·후속 발송 승인 경계 | 사람의 변경 확인 흐름은 구현. 실제 AI 제공자·실행 도구·근거 저장·실패 및 권한 검사 남음 |
| 4. 운영 준비 | 운영 인증·직원 계정 관리, PostgreSQL, 서비스 분리, 백업/복원 | 로컬 인증·직원 사용 중지/재개와 인계 확인·회사 분리·암호화 백업/복원 구현. 신규 초대·메일 인증·관리자 계정 흐름·실제 PostgreSQL 동시 접속·운영 서비스 이미지·원격 백업과 재해 복구 남음 |
| 5. 전체 검수 | PC·모바일에서 합의한 업무를 처음부터 끝까지 수행하고 중대 오류 해결 | 각 구현 단위 검사 진행. 외부 연동을 포함한 전체 사용자 검수·모바일 회귀·부하·장애 및 복구 검수 남음 |
| 6. 승인 배포 | staging 확인 → 본인의 GitHub 승인 → Railway 싱가포르 운영 실행 확인 | 워크플로 골격 존재. 계정·저장소·Railway·도메인 연결, 시험 배포 및 승인 배포 실검증 남음 |

업무 기록·단계·고객 수정본·기한·종료·재배정·운영 기준·첫 연락 성과는 기존 구현을 유지하고 필요한 오류만 수정한다. 새 화면을 임의로 추가 구축 범위에 넣어 첫 배포의 종료 조건을 늘리지 않는다.

프레임에 있는 첨부 자료·상세 보고서 등 첫 배포 여부가 미정인 기능은 삭제하거나 구현 완료로 간주하지 않는다. 별도 후속 범위 목록으로 남기고 실제 기업/사용자 검수에서 우선순위를 확인한다. AI는 현재 요구사항에 남아 있으며 임의로 제외하지 않는다.

## 외부 연결 의존성

사용자는 GitHub·Railway·발신 메일 계정이 준비되지 않았다고 답했다. 이 사실은 연결 대기로 유지하고 반복해서 준비 여부를 묻지 않는다. Emergent API와 AI 제공자 정보도 아직 연결되지 않았다. 그동안 내부 구현·제공자 대체 검수·배포 산출물 준비를 진행할 수 있지만, 실제 운영 성공이라고 표시할 수 없다.

현재까지의 상세 결과는 [진행 현황](06-progress.md)과 [백업·복원 검수](06g-backup-and-restore.md)를 따른다.
