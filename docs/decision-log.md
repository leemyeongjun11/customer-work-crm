## 변경 기록 규칙

6차 시작 결정: 사용자 요청으로 **MVP 범위 구축 → 검수 및 안정화 → 배포(CI/CD) → 추가 구축** 순서로 진행한다. 사용자가 프레임 검수 완료를 알리고 시작에 동의했으므로 현재 수정된 화면과 shadcn 기본 테마를 초기 구축 기준으로 사용한다. 브라우저의 개별 검수 선택값을 자동 변경하지 않는다. 첫 구현은 로그인·권한·상담/업무/메모 저장이며, AI 요구는 유지한 채 제공자 연결 단계로 진행한다. 상세는 [6차 계획](06-build-and-acceptance.md)과 [첫 구현 검수](06a-first-working-slice.md). 기존 GitHub 본인 승인 후 운영 배포 조건을 유지한다.

사용자가 승인하거나 수정하면 결정 ID와 내용, 영향을 받는 화면·문서·코드, 검증 결과를 함께 기록합니다. 프레임 검수 전에는 P 항목을 확정 합의로 승격하지 않습니다.
