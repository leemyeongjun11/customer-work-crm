> 2026-09-12 프레임 02 변경: 사용자 요청으로 목업 범위를 전체 화면으로 확장했습니다. 아래의 ‘이번 프레임에서 제외’는 프레임 01 당시 범위이며, 현재는 접수·계정·KPI·설정 편집·연동·예외 상태도 검수합니다. [전체 화면 목록](05c-screen-inventory.md)과 [검수 단계 기준](05b-full-frame-review.md)을 참고합니다.

## 기존에 정한 화면 원칙

첫 화면은 **오늘 할 일**입니다. 기한이 지난 업무, 오늘 확인할 업무, 확인이 필요한 항목을 구역별로 보여줍니다. 업무와 연결된 AI 제안은 같은 카드 안에 표시해 중복 업무로 보이지 않게 합니다.

카드에는 해당 고객의 **초기 요청 원문을 한 줄로 미리보기** 표시합니다. 줄바꿈은 공백으로 보여주고 긴 내용은 말줄임표로 자릅니다. AI 요약이나 이후 상담 메모로 대체하지 않으며, 원문 데이터는 유지합니다. 전체 내용은 영업건 상세의 접수 원문에서 확인합니다.

완료한 업무는 오늘 할 일에서 제거합니다. 오늘 화면에 “완료” 탭을 두지 않으며, 완료·관리 제외 기록과 완료 취소는 해당 영업건 상세에서 확인합니다. 앞으로 할 일은 별도 예정 업무 보기로 분리합니다.

| 화면 | 핵심 목표 | 주요 행동 |
|---|---|---|
| 오늘 할 일 | 지금 무엇을 해야 하는지 빠르게 판단 | 연락 결과 기록, 완료 처리, 기한 설정, 제안 검토 |
| 예정 업무 | 이후 약속을 확인 | 기한 확인·변경, 상세 이동 |
| 확인 필요 | 날짜·다음 행동·직원 판단이 없는 상태 해소 | 기한 설정, 다음 행동 등록, 종료·담당자 변경 검토 |
| 영업건 목록 | 상담부터 서비스까지 전체 진행 확인 | 단계별 보기, 검색, 상세 이동 |
| 영업건 상세 | 고객별 다음 행동과 맥락을 함께 파악 | 업무·메모·이력·자료·고객 정보 확인 |
| 결과 기록 창 | 업무 처리 후 최소 입력으로 기록 | 결과·실제 수행 시각 입력, 메모는 선택 |
| 제안 검토 창 | 내용과 영향을 확인한 뒤 확정 | 수정, 승인, 사유를 남겨 제외, 다음 확인 날짜 |

## 5차 프레임에서 제시한 배치

```text
오늘 할 일
  ├─ 기한 초과 / 오늘 확인할 업무 / 확인 필요 요약
  ├─ 오늘 업무: 지연 → 오늘 → 확인 필요 구역
  ├─ 예정 업무
  └─ 확인 필요
영업건
  ├─ 진행 중 단계별 보드
  ├─ 서비스 완료·종료 보관 목록
  └─ 상세: 업무와 다음 행동 / 상담 메모 / 변경 이력 / 자료
AI 활동                 [이번 배치 제안]
운영 기준               [이번 배치 제안: 관리자용 읽기 화면]
검수 도구               [시연 전용, 운영 화면에서 제거 예정]
```

상세 화면의 오른쪽에는 고객 정보를 두고, 본문은 다음 행동을 먼저 보여줍니다. 모바일에서는 고객 정보를 본문 아래로 배치합니다. 영업건 단계 보드는 좁은 화면에서 내부 가로 스크롤로 탐색합니다. 별도의 KPI 화면·설정 편집 화면은 이번 프레임 범위에 포함하지 않았습니다.

## 상태별 표시

| 상황 | 화면 행동 |
|---|---|
| 신규 문의 도착 | 담당자·기한과 함께 오늘에 표시. 마감이 내일이어도 신규 문의는 오늘 확인 가능 |
| 완료 | 오늘 목록에서 제거, 상세 완료 기록에 남김 |
| 기한 미정 | “기한 확인 필요”로 표시. AI가 날짜를 꾸며내지 않음 |
| 다음 행동 없음 | 다음 행동 또는 확인 날짜 등록을 안내 |
| 종료 승인 대기 | 남은 업무와 알림 유지. 확정 시 영향 확인 |
| 저장·발송 실패 | 성공처럼 표시하지 않음. 입력 내용 유지·재시도 안내 |
| 연동 지연 | 연결 상태와 마지막 확인 시각 표시, 기존 업무 확인 가능 |
| 최초 데이터 없음 | 신규 상담이 들어오면 어떻게 보이는지 안내 |
| 오늘 업무 없음 | 예정 업무와 영업건 기록으로 안내 |
| 권한 없음 | 접근 불가 안내. 권한 밖 데이터는 표시하지 않음 |
| 작성 중 닫기 | 이번 세션 안에서 초안 보관·다시 열기. 새로고침 지속 보관은 미구현 |

로딩 중, 로그인 만료, 서버 버전 충돌, 파일 오류, 이메일 결과 불명 등 실제 연결 상태는 후속 구현에서 해당 API 오류와 함께 검수합니다. 이번 검수 도구에 없다는 이유로 운영 요건이 제거된 것은 아닙니다.
