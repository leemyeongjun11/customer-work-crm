# 네 번째 구현 — 운영 기준과 첫 연락 성과

작성: 2026-09-13. 현재 단계는 **6.1 MVP 구축 중**이다. 외부 메일·Emergent·AI·Railway 연결 완료를 의미하지 않는다.

## 검수 위치

- `/live/settings`: 관리자 계정의 ‘운영 기준’ 메뉴.
- `/live/metrics`: 관리자와 직원의 ‘첫 연락 성과’ 메뉴.
- 기존 영업건·프레임 검수 데이터는 유지한다.

## 운영 기준

관리자는 신규 상담의 기본 담당자와 회사 휴일을 저장할 수 있다. 회사 안의 활성 사용자만 담당자로 지정한다. 휴일은 YYYY-MM-DD 형식으로 한 줄에 하나씩 입력하며, 중복·잘못된 날짜는 거부한다. 주말은 자동 제외하지만 법정 공휴일은 자동으로 채워지지 않는다.

변경 이유와 적용 범위 확인을 받는다. 기본 담당자와 첫 연락 기한 계산은 새 상담부터 적용한다. 기존 상담의 담당자·현재 기한·원래 기한을 소급 변경하지 않는다. 정기 알림의 휴일 판단에는 최신 휴일 설정을 사용한다. 첫 연락은 다음 영업일 17시, 알림은 영업일 15시와 16시 30분인 기존 기준을 유지한다.

설정 변경 전후 값·수행자·이유를 DB에 기록한다. 버전 충돌 시 최신 설정을 확인하면서 작성 중인 입력을 유지할 수 있다. 같은 요청의 재실행은 중복 이력을 만들지 않는다. 신규 상담에는 적용된 설정 버전과 기한 계산 정책을 함께 보존한다. 과거 상담의 정책을 추정하여 소급 기록하지 않는다.

## 첫 연락 성과 — 산정 검수안

목표는 **기한 내 첫 연락 완료율 100%**이며 실제 달성 성과와 구분한다.

- 조회 기간에 **접수 당시 원래 기한**이 속하고, 집계 시각에 그 기한이 도래한 상담을 분모로 사용한다.
- 실제 연락 시각이 원래 기한 이내이고, 통화 연결 또는 부재 후 안내 문자 발송을 완료 기록한 상담을 분자로 사용한다. 전화 시도만으로는 완료되지 않는다.
- 아직 기한 전인 상담은 별도로 표시하고 비율에서 제외한다. 분모가 0이면 ‘집계 대상 없음’으로 표시한다.
- 기한 연장이나 영업건 종료로 지연 실적이 사라지지 않는다. 완료를 취소하면 현재 기록에 맞춰 다시 집계한다.
- 관리 제외 사유별 KPI 제외 기준은 기업 검증 전이다. 현재는 관리 제외도 분모에 포함하고 화면에 ‘검수안’이라고 명시한다.
- 관리자는 회사 전체, 직원은 현재 본인 담당 건만 조회한다. 담당자별 과거 귀속 실적 보고서는 이번 범위가 아니다.
- DB에서 전체 대상의 수치를 계산한다. 상세 근거는 앞 100건을 표시하며 조회 범위는 최대 366일이다. 비율은 소수점 한 자리까지 버려 100% 미만을 반올림으로 100%라고 표시하지 않는다.

## API

| 메서드·경로 (`/api/v1` 기준) | 동작 |
|---|---|
| `GET /admin/settings` | 관리자에게 현재 기준, 회사 사용자, 최근 변경 이력 30건 제공 |
| `PATCH /admin/settings` | `defaultAssigneeId`, `holidays`, `expectedVersion`, `reason`, `confirmed`로 변경. 중복 방지 키 필요 |
| `GET /metrics/first-contact?from=YYYY-MM-DD&to=YYYY-MM-DD` | 권한 범위 내 집계, 산정 기준, 최대 100건의 근거 제공 |

## 확인 결과

- `pnpm check`: 타입 검사, 기존 21개 검사와 API 통합 검사 9개(총 30개), 웹 빌드 통과.
- 설정 관리자 권한, 회사 분리, 날짜 검사, 중복 요청, 버전 충돌, 신규 상담 정책 적용, 기존 상담 보존을 격리 DB에서 확인했다.
- 기한 정각 문자 완료, 지연 통화, 미완료, 미래 기한, 기한 연장, 관리 제외·종료, 완료 취소의 집계를 확인했다.
- 별도 로컬 관리자 브라우저에서 기존 담당자·휴일 값을 그대로 저장하고 변경 이력 생성을 확인했다. 예시 상담과 사용자의 편집은 변경하지 않았다.
- 브라우저에서 기간을 9월 1일~30일로 변경하여 아직 기한 전인 예시 2건과 ‘집계 대상 없음’ 표시를 확인했다. 날짜 입력의 `input` 이벤트도 반영하도록 수정한 뒤 웹 빌드와 기간 조회를 다시 확인했다.
- 실제 저장 화면과 기존 프레임을 분리하여 필요한 코드를 지연 로드하도록 변경했다. 기존 `/review` 화면 로드와 검수 선택값 유지를 확인했다. 속도 향상 수치를 실측한 것은 아니다.

## 남은 범위

실제 회사 휴일 확정·달력 검증, KPI 제외 기준 사용자 검수, 실제 PostgreSQL 동시 접속, 외부 연동과 발송, 전체 모바일 회귀 검수, 백업·복구, 운영 인증·CI/CD 배포는 남아 있다. GitHub·Railway·발신 메일은 사용자가 아직 준비되지 않았다고 답했으며 외부 배포나 발송을 활성화하지 않았다.
