# 등록된 직원의 사용 상태 관리

2026-09-13, 여덟 번째 구현 단위. 현재 **6.1 MVP 구축 중**이다.

## 화면과 처리 순서

관리자는 `/live/accounts`의 **직원 계정**에서 회사에 등록된 직원과 사용 중/사용 중지 상태를 확인한다. 일반 직원에게는 메뉴와 API를 허용하지 않는다. 신규 초대, 비밀번호 재설정, 관리자 권한 변경, 운영 인증 서비스 연결은 이번 구현에 포함하지 않는다.

1. **사용 중지 검토**를 누르면 신규 문의 기본 담당자 여부와 진행 중인 영업건을 조회한다. 업무가 모두 완료됐더라도 영업건 자체가 진행 중이면 인계 대상으로 본다.
2. 기본 담당자라면 운영 기준에서 다른 활성 직원으로 변경한다. 진행 중인 영업건은 기존의 담당자 변경 제안 → 영향 확인 → 관리자 확정 흐름으로 인계한다. 화면에서 해당 영업건으로 이동할 수 있다.
3. 최신 상태를 다시 확인한다. 인계 항목이 없으면 이유를 입력하고 영향 확인 후 **사용 중지 확정**을 누른다. 서버도 저장 시점에 인계 조건을 다시 검사한다.
4. 사용 중지는 삭제가 아니다. 완료·종료된 영업건, 상담 기록과 실제 수행자의 과거 이력을 보존한다. 중지한 직원은 담당자 선택지에서 제외하고, 기존 세션을 삭제해 다음 인증 요청부터 차단한다. 이미 승인되어 처리 중인 요청까지 취소하는 기능은 아니다.
5. **사용 재개 검토** → 이유·확인 → 확정으로 같은 직원 권한을 재개한다. 기존 세션은 복원하지 않고 다시 로그인해야 한다. 인계한 영업건은 자동으로 되돌리지 않는다.

이 흐름은 정상적인 인계 후 사용 중지를 위한 것이다. 인계 전 긴급 계정 차단·관리자 복구·비밀번호 유출 대응은 운영 인증 구축에서 별도로 다룬다. 관리자 계정은 이 화면에서 중지하거나 권한을 바꿀 수 없다.

## API와 저장 기준

| 요청 | 기능 |
|---|---|
| `GET /api/v1/admin/users` | 회사 직원 목록, 최근 사용 상태 변경 이력 30개 |
| `GET /api/v1/admin/users/{id}/preview` | 최신 상태·버전, 기본 담당자 여부, 진행 중인 영업건 수와 앞 100건 |
| `POST /api/v1/admin/users/{id}/status` | `active`, `expectedVersion`, `reason`, `confirmed`와 `Idempotency-Key`로 변경 |

회사와 관리자 권한은 인증 세션에서 결정한다. 임의 역할·회사 입력은 받지 않는다. 자기 자신과 관리자 대상 변경은 차단한다. 같은 요청의 중복 실행은 같은 결과를 반환하고, 다른 내용의 요청 키 재사용과 오래된 버전은 409로 거절한다.

회사 설정 → 대상 사용자 순으로 잠그고 상태 변경·세션 폐기·이력·중복 방지 응답을 한 트랜잭션에 저장한다. 신규 접수/담당자 재배정의 활성 사용자 잠금과 연계한다. 로그인도 비밀번호 확인 후 사용자 상태와 버전을 잠금 안에서 다시 확인해 중지·재개 사이의 오래된 로그인 요청을 막는다. 실제 여러 PostgreSQL 프로세스의 경합 검사는 후속 운영 검수 대상이다.

`crm_users.version`과 `crm_account_history`를 추가했다. 해당 이력은 암호화 백업에 포함한다. 06g 전달 버전의 스키마 지문을 명시적으로 인식해 이전 백업에 사용자 버전 1과 빈 계정 이력을 추가하여 복원한다. 알 수 없는 스키마 지문을 무조건 허용하지 않는다.

## 검수와 남은 일

별도 테스트 DB에서 관리자/직원/다른 회사 권한, 허용 입력, 기본 담당자·인계 전 중지 차단, 기존 제안 승인으로 인계, 중복·동시 변경 충돌, 세션 삭제·중지 중 로그인 거절·재개 후 재로그인, 담당자 선택지 제외, 계정 이력 백업과 이전 백업 호환을 검증한다.

외부 직원 초대·메일 인증·비밀번호 재설정·관리자 수명주기·운영 인증 연결은 남아 있다. 기존 로컬 사용자 계정을 임의로 새 계정으로 교체하지 않는다. 이 단위 완료를 운영 계정 관리 전체 완료나 배포 완료로 표시하지 않는다.

실행 결과: 전체 로컬 검사 43개(업무·배포 규칙 21개, API 22개)와 타입 검사·웹 빌드 통과. 별도 메모리 DB에서 기본 담당자 중지 차단, 인계가 끝난 직원의 중지·재개와 사유·이력 저장을 화면으로 확인했다. 사용 중인 회사의 두 계정은 변경하지 않았다. 실제 이전 백업을 `.local-data/restore-accounts-compat-20260913`에 복원해 영업건 2개/업무 3개와 새 사용자 버전 호환을 확인했다.
