# 5차 — UI 디자인과 프레임 01 검수

작성일: 2026-09-12. 상태: **5.1 전체 프레임 02 구현 / PC·모바일 사용자 검수 대기**.

현재 범위는 [전체 화면 검수 기준](05b-full-frame-review.md)과 [화면 목록](05c-screen-inventory.md)이 우선합니다. 프레임 01의 일부 화면만 검수하는 방식에서 **52개 화면·확인창·상태 전체를 검수**하는 방식으로 확장했습니다. 아래 프레임 01 구현 표는 이전 회차 기록입니다.

검수 페이지: <http://127.0.0.1:4173/review>. 모바일: [접속 안내](05b-full-frame-review.md#모바일에서-열기). **전체 프레임 검수와 수정 반영을 마친 뒤 UI 의사결정, 그다음 테마 선택**으로 진행합니다. 제작자 검증은 사용자 승인을 대신하지 않습니다.

## 진행 방식

1. **프레임 목업:** 실제로 눌러볼 수 있는 화면으로 정보 배치·이동·처리 흐름을 검수하고 수정합니다.
2. **UI 의사결정:** 피드백이 반영된 화면을 기준으로 정보 밀도, 요약 카드 필요성, 주요 버튼 위치, 상세 표시 방식, 오류·빈 상태 표현을 결정합니다.
3. **테마 선택:** 구조가 안정된 같은 화면에 색상·서체·간격 후보를 적용해 비교하고 선택합니다. 접근성·작은 화면을 함께 확인합니다.

사용자 요청에 따라 프레임 단계는 **shadcn 기본 테마**를 사용합니다. 현재 적용값은 Neutral 라이트 테마와 New York 컴포넌트 스타일입니다. 기존 임의 색상 CSS는 제거하고 Tailwind CSS와 shadcn 공식 컴포넌트로 교체했습니다. 최종 브랜드 테마는 이후 단계에서 검토하며, 현재 프레임의 테마 사용 기준은 확정입니다. [기술·테마 설정](05a-ui-stack-theme.md)

## 검수 위치

로컬 개발 서버: <http://127.0.0.1:5173>. 실행법은 [README](../README.md)를 참고합니다.

| 화면 | 확인할 내용 |
|---|---|
| 오늘 할 일 | 초과·오늘·확인 필요 구역을 읽는 순서, 한 카드의 정보량 |
| 연락 결과 기록 | 메모 없이 결과 기록, 실제 수행 시각, 통화 부재 처리 |
| 영업건 | 진행 단계별 보기와 검색, 서비스 완료·종료 분리 |
| 영업건 상세 | 다음 행동 우선, 고객 정보 위치, 메모·이력·자료 탭 |
| 제안 검토 | 이메일 수신자·내용, 종료 영향, 담당자 변경 영향 |
| AI 활동 | 어떤 영업건에 어떤 처리를 했는지 파악 |
| 운영 기준 | 현재 정책을 이해할 수 있는지 확인. 변경 기능 없음 |

## 추천 검수 순서

1. 첫 화면에서 **가온설비 → 연락 결과 기록**을 열어 봅니다. 전화만 시도하면 미완료가 유지되고, 통화 연결 또는 부재 후 문자 발송을 기록하면 오늘 업무에서 사라집니다. 상세에는 완료 기록이 남습니다.
2. **해솔사무소 → 기한 설정**에서 날짜와 이유를 입력합니다. 기한 미정 항목이 해당 날짜의 업무로 이동하는지 확인합니다.
3. **메이플스튜디오 → 이메일 검토**에서 받는 사람과 내용을 확인합니다. 승인 후 발송은 성공 흐름 시연이며 실제 전송은 없습니다. 다음 확인 날짜를 선택하면 회신 확인 업무를 따로 만듭니다.
4. **다온오피스 → 제안 검토**에서 종료 시 남은 업무와 알림 중단 안내를 확인합니다. 확인 전까지 기존 업무는 유지됩니다.
5. **검수 도구**에서 저장 실패·이메일 실패·빈 화면·연결 지연을 전환해 봅니다. 오류가 나도 입력과 미완료 상태를 유지하며 “재시도 · 시연”으로 복구를 확인합니다.

역할 전환은 화면 검수용입니다. 일반 직원은 김담당의 영업건만 보고, 관리자는 전체를 봅니다. AI 시연 역할은 전체 영업건에 메모·날짜 미정 업무를 기록할 수 있지만, 승인·설정 변경은 할 수 없습니다. 실제 서버 권한과 AI의 근거 있는 자동 실행은 다음 구현 단계에서 연결합니다.

## 구현 범위와 남은 일

| 이번에 구현 | 아직 연결·구현하지 않은 것 |
|---|---|
| React 화면·URL 이동·세션 내 상태 | 로그인·서버 인증·회사별 데이터 격리 |
| 완료/기한/메모/고객 수정·제안 검수 시연 | 실제 CRM API·DB·업무 트랜잭션 |
| 고정 날짜와 가상 문의 도착 | 운영 달력·웹훅·SSE·보정 수집 |
| 이메일 성공/실패 화면 시연 | 실제 메일 제공자·발송 결과 조회·배치 실행 |
| 가상 AI 처리 기록 | AI 모델·에이전트 실행·실제 근거 검사 |
| 파일 목록 배치 예시 | 업로드·다운로드·첨부 발송 |
| 초안 임시 보관 | 새로고침 후 복구·다른 기기 동기화 |
| 프런트엔드 빌드와 규칙 테스트 | 실제 Railway 배포와 환경 비밀값 설정 |

운영 준비 표시 `CRM_APP_READY`와 배포 활성화 `CRM_DEPLOY_ENABLED`는 활성화하지 않습니다. API/Worker/Scheduler의 실제 코드·컨테이너·연결 검증 전에 목업만으로 운영 배포를 통과시키지 않습니다.

## 피드백 기록

### 프레임 02 — 다음 행동의 업무 종류 선택

- 사용자 승인: 업무 종류 선택 → 구체적 내용 → 처리 날짜 순서로 등록. 현재 영업 단계에 맞는 종류를 먼저 보여주고 다른 단계의 업무도 선택 가능.
- 일반 종류의 설명과 날짜는 선택, ‘기타 고객 관련 업무’의 설명은 필수. 선택하지 않았거나 기타 설명이 공백이면 저장하지 않음.
- 등록 전 제목 미리보기 제공. 종류와 설명을 저장하고 카드에는 ‘종류 · 설명’으로 표시. 날짜가 없으면 ‘기한 확인 필요’ 유지. 종류 선택으로 영업건 단계나 첫 연락 기준이 자동 변경되지는 않음.
- 목록은 서비스 기업 공통 업무의 초기안이며 실제 기업의 절차에 맞춰 조정 가능. 자유 설명의 업무 관련성을 AI가 판정하거나 무관한 문구를 자동 차단하는 기능은 아님.
- 현재 UI 등록에는 종류 선택을 요구하며 기존 가상 업무·내부 명령의 제목 입력과 호환 유지. 실제 API 계약 반영은 연결 단계에서 별도로 검증.

### 프레임 02 — 상세 탭과 수정 기능 간격

- 사용자 피드백: ‘업무 제목 수정’이 ‘업무와 다음 행동’ 탭과 너무 가까움.
- 수정 링크를 탭 바로 아래에서 제거하고, 탭과 24px 간격을 둔 ‘다음 행동’ 제목 행의 ‘업무 등록’ 옆에 배치. ‘기존 메모 수정’도 상담 메모 제목 행으로 통일.
- 수정 기능은 테두리와 클릭 여백을 추가하고, 좁은 화면에서는 줄바꿈하여 겹침을 방지. 사용자 재검수 대기.

### 프레임 02 — AI 활동의 처리 주체와 승인 상태

- 사용자 승인: 반짝임 아이콘만으로 AI 사용 여부를 판단하지 않도록 글자 표시를 추가.
- AI 직접 반영은 ‘AI 처리’, 제안 생성은 ‘AI 제안’, 일반 자동화는 ‘시스템 자동 처리’, 직원 기록은 ‘직원 처리’로 표시.
- 제안 생성 이력은 해당 제안 ID와 연결하여 현재 ‘직원 승인 대기 / 승인 완료 / 제안 제외 / 검토 종료’를 별도로 표시. 같은 고객의 다른 기록에 승인 대기를 붙이지 않음.
- 실제 AI가 연결된 것은 아니며 기존 가상 데이터 안내 유지. 사용자 재검수 대기.

### 프레임 02 — 기한 초과 카드의 행동 문구

- 사용자 피드백: 미처리된 기한 초과 업무에서 ‘완료 기록’, ‘연락 결과 기록’이라는 버튼이 이미 처리한 업무처럼 느껴짐.
- 반영: 기한이 지난 첫 연락은 **지금 연락하기**, 일반 업무는 **지금 처리하기**로 표시. 이메일은 발송 전 검토가 필요하므로 기존 검토·초안 문구 유지.
- 열린 처리창에는 미처리 업무임을 표시하고, 직접 연락·업무 수행 후 결과를 기록하도록 안내. 버튼을 누르는 것만으로 연락·완료 처리가 발생하지 않음.
- 상태: 문구 수정 반영, 사용자 재검수 대기.

피드백은 **화면 / 불편한 점 / 원하는 변화** 형식이면 충분합니다. 예: “오늘 할 일 / 요약 카드가 커서 업무가 아래에 있음 / 카드 높이를 줄이고 싶음”.

| 회차 | 사용자 피드백 | 반영 내용 | 검수 상태 |
|---|---|---|---|
| 프레임 01 | 아직 받지 않음 | 첫 검수본 구현 | 사용자 검수 대기 |
| 프레임 01 수정 | Tailwind CSS·shadcn 사용, 프레임은 shadcn 기본 테마 | 버튼·카드·배지·입력·선택·Dialog 교체, Neutral 토큰 적용 | 변경 반영, 배치 검수 대기 |
| 프레임 01 수정 2 | 카드에서 해당 건의 초기 요청을 한 줄 미리보기 | 업무·제안·다음 행동 없음·영업건 카드에 접수 원문 미리보기 추가. 긴 내용은 말줄임, 전체 원문은 상세에서 확인 | 변경 반영, 검수 대기 |

프레임 배치 승인 → UI 선택사항 기록 → 테마 후보 비교 순으로 진행합니다. 사용자 답변 없이 검수를 승인 처리하지 않습니다.
