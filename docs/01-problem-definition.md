# 1차 — 문제 정의

## 1. 사용자 정의

가정하는 기업은 상담을 받아 계약하고 서비스를 제공하는 기업입니다. 시공·설비·방문 점검·유지보수 등은 업무를 설명하기 위한 예시이며 특정 업종으로 확정하지 않았습니다. 실제 사용자는 상담과 후속 업무를 처리하는 사무직·영업 담당 직원입니다. 관리자는 담당자와 운영 기준을 관리합니다.

현재 프로젝트 참여자는 AI 리빙랩 수업의 학생이며, 연계 기업이나 기업이 제시한 문제는 없습니다. 아래 문제는 실제 기업 인터뷰로 검증되지 않은 **프로젝트 가설**입니다.

## 2. 병목 가설

상담이 웹사이트 관리자 화면과 별도 엑셀에 흩어져 있고, 담당자별 다음 행동과 기한을 추적·경고하는 기능이 부족하면 해야 할 연락을 놓칠 수 있습니다. 외근 등 전화하기 어려운 상황에서 요청을 확인한 후 다시 처리할 장치가 없는 상황을 가정합니다.

설명용 사례: 신규 상담 후 다음 영업일 이내 첫 전화를 해야 했지만 누락했고, 2주 뒤 영업건을 정리하며 발견했습니다. 실제 발생 사실이나 일반적인 빈도를 입증하는 사례는 아닙니다.

후속 연락, 견적 전달, 고객 회신 확인, 계약 후 서비스 진행에서도 다음 행동이나 확인 날짜가 없으면 비슷한 누락이 생길 수 있다는 추가 가설을 둡니다.

## 3. 해결 대상

첫 번째 핵심은 신규 상담의 첫 연락 누락 방지입니다. 신규 문의를 담당자·첫 연락 기한과 연결하고, 오늘 해야 할 일과 지연된 업무를 한 화면에서 확인하게 합니다. 이후 계약·서비스 제공까지 다음 행동과 확인 날짜를 이어 관리합니다.

## 4. 수동·자동 경계

| 자동 처리 | 사람이 처리·확인 |
|---|---|
| 신규 문의 반영, 전담 담당자 배정, 기준에 따른 첫 연락 기한 계산 | 실제 전화·대면·화상 상담과 고객과의 협의 |
| 기한 초과 분류, 영업일 15:00 통합 이메일 알림, 16:30 첫 연락 추가 알림 | 통화 결과와 실제 수행 시각 기록 |
| 근거가 있는 영업 메모·요약·다음 행동 반영 | 날짜가 불명확한 후속 업무의 기한 확정 |
| AI가 종료·담당자 변경·후속 발송 제안 생성 | 권한 있는 직원이 제안 내용과 영향을 확인 후 실행 |

AI는 사용자·권한·시스템 설정을 변경할 수 없습니다. 자세한 범위는 [최신 API 명세](04d-core-api-contract.md)를 따릅니다.

## 5. 핵심 KPI

**목표: 첫 연락 기준을 지킨 완료율 100%.** 자동화만으로 달성을 보장한다는 뜻이 아닙니다. 실제 연락 수행과 기록이 필요합니다.

첫 연락 기준은 기존 설계 문서의 “접수일 다음 영업일 17:00까지”로 구체화합니다. 영업일은 한국 시간 기준 주말·공휴일을 제외하며, 달력 데이터와 정책 버전을 기록해야 합니다. 고객 연락은 10:00~11:30 / 14:00~17:00을 기본 권장 시간으로 하고 고객의 연락 희망을 우선 고려합니다. 개인적으로 5~10분 기다렸다 전화하는 습관은 자동화의 필수 지연 규칙으로 넣지 않습니다.

완료 인정은 통화 연결, 또는 부재 후 안내 문자 발송입니다. 전화만 시도하고 문자를 보내지 않으면 미완료로 둡니다. 시스템 입력 시각과 실제 수행 시각을 구분합니다.

**측정안 — 구현·기업 검증 시 최종 확인:**

`기간 내 최초 첫 연락 기한이 도래한 대상 중, 최초 기한 이내 완료한 건수 ÷ 같은 기간 최초 기한이 도래한 전체 대상 건수 × 100`

- 기한 연장으로 원래 기한이나 기존 지연 실적을 지우지 않습니다.
- 서비스 대상이 아닌 문의의 분모 제외 기준은 종료 사유·담당자 확인과 함께 별도로 정해야 합니다. 임의로 종료해 지연 기록을 숨기지 않습니다.
- 전화 연결률은 위 첫 연락 완료율과 별개입니다. 문자로 완료를 인정한 건수를 구분할 수 있어야 합니다.
- 대상이 0건이면 100%로 표시하지 않고 “집계 대상 없음”으로 표시합니다.
- 초기 기준치와 실제 개선치는 아직 측정하지 않았습니다. 이번 프레임에는 KPI 실적 차트를 넣지 않았습니다.
