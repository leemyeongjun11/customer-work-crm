# 상담 기록으로 다음 업무 제안받기

2026-09-14 구현. API 서버 설정과 이 코드의 배포가 완료되면 Groq의 실제 모델에 제안을 요청할 수 있다. 자동 검사는 가짜 AI 응답을 사용하며 실제 상담의 정확도·시간 절감 효과는 별도 검수한다. 기존 `/live/ai-demo`의 준비된 시나리오와 구분한다. 학교 서버 이전은 아직 수행하지 않았다.

## 직원이 사용하는 순서

1. 고객과 상담한 뒤 예시 상담 메모를 저장한다.
2. ‘완료 후 다음 진행 정하기’에서 **AI로 다음 업무 정리**를 누른다.
3. 상담 기록과 기존 미완료 업무가 Groq API로 전송된다.
4. AI가 요약, 고객 상황, 단계, 다음 업무, 날짜, 판단 근거와 확인할 사항을 제안한다.
5. 직원이 내용을 고치고 확인란을 선택한 뒤 **승인하고 업무에 반영**을 누른다.

AI 버튼만으로 업무를 생성하거나 고객에게 연락하지 않는다. 같은 요청 연결도 기존 비교·승인 방식으로 유지한다. 상담 기록을 자동으로 듣거나 전화 결과를 알아내는 기능은 포함하지 않는다.

예시 상담: “2026년 9월 18일까지 에어컨 3대 점검 견적을 보내 주세요. 방문 날짜는 나중에 정하겠습니다.”

시험할 목표는 견적서 작성·전달, 2026-09-18 기한, 방문 날짜 확인 질문의 제안이다. 이는 실제 모델 출력이 검증된 사례가 아니다. 연결 후 한국어 예시 상담으로 날짜 정확도, 빠진 업무, 직원 수정 시간 등을 확인해야 한다.

## 서버에서 켜는 방법

다음 설정은 **웹 화면이 아니라 API 서버**에 저장한다.

| 환경 변수 | 설정 |
|---|---|
| `CRM_AI_ENABLED` | `true`일 때만 AI 요청 허용. 기본은 꺼짐 |
| `GROQ_API_KEY` | Groq 계정에서 발급한 API 키. 비밀값으로 등록 |

둘 다 설정해야 AI 버튼을 사용할 수 있다. 모델은 `qwen/qwen3.6-27b`로 고정되어 있다. 브라우저에 키를 입력하는 기능이나 공개 API 주소를 바꾸는 기능은 제공하지 않는다.

### 현재 Railway에서 시험할 경우

1. 이 변경을 검토·테스트한 뒤 시험 환경에 배포한다. 로컬 파일 수정만으로 현재 사이트가 바뀌지는 않는다.
2. [Groq Console](https://console.groq.com/)에서 사용할 계정의 **Free Plan** 여부를 확인하고 API 키를 발급한다.
3. Railway 프로젝트의 `staging` → **api** 서비스 → Variables에 위 두 값을 등록한다.
4. 변경 설정이 API 서비스 실행에 반영된 뒤 CRM을 연다.
5. 예시 상담으로 다음 진행 화면을 열어 AI 제안을 요청하고 확인한다.

키는 GitHub 소스, 프런트엔드의 `VITE_` 변수, 문서 또는 채팅에 넣지 않는다. 사용 설정이 켜졌다는 표시는 키와 환경 변수가 있다는 뜻이며, 실제 모델 연결에 성공했다는 검증 결과가 아니다.

실패하면 기존 입력이 유지되어 사람이 직접 다음 진행을 선택할 수 있다. `CRM_AI_ENABLED=false`로 바꾸면 외부 호출이 중단되고 기존 규칙 기반 기능을 계속 사용할 수 있다.

### 학교 서버에서 시험할 경우

Groq 방식의 구조는 **브라우저 → 학교 서버의 CRM·API·DB → Groq의 Qwen 모델 → 직원 검토·승인**이다. 모델이 외부에서 실행되므로 학교 서버에 GPU는 필요하지 않다. 상담 데이터가 Groq로 전달되므로 학교 서버의 외부 HTTPS API 접속과 데이터 사용 조건을 확인해야 한다.

학교 서버의 OS, SSH·Docker 사용 가능 여부, CPU/RAM/디스크, 도메인·HTTPS 제공 여부, 외부 접속 범위를 확인한 뒤 배포 설정을 작성한다. 현재 저장소에는 Node.js 24 기반 web·api·worker·scheduler Dockerfile과 PostgreSQL 실행 구조가 있다. 다음 항목은 학교 환경에 맞춰 준비해야 한다.

- 네 서비스와 PostgreSQL의 실행 설정 및 DB 영구 저장 경로
- 내부 API 주소와 HTTPS 프록시 설정: 현재 웹 프록시는 Railway 내부 주소 또는 127.0.0.1만 허용한다.
- `PUBLIC_APP_URL`, 내부 인증용 비밀값, 최초 시험 계정 설정
- 컨테이너가 요구하는 `release.json`의 학교 배포용 생성 절차
- 위 AI 환경 변수, 예시 데이터, 백업·복원 및 접속 검수

이 문서만으로 학교 서버 배포가 끝난 것은 아니다. 학교에 Qwen 모델 자체를 등록해 실행하는 GPU 서비스가 있다면, 그것은 Groq를 호출하는 구성과 다르다. GPU 종류·VRAM 및 학교 모델 API 규격을 확인한 뒤 연결 방식을 정한다.

## 무료 사용 범위

Groq의 Free Plan에는 요청 횟수와 처리 토큰 한도가 있다. 코드에는 자동 재시도나 유료 제공업체로 바꾸는 경로가 없다. API 라우트는 클라이언트별 분당 2회까지 허용하고, 같은 API 프로세스에서 같은 직원·영업건의 동시 요청을 차단한다. Groq의 한도 오류는 직원에게 알리고 수동 입력을 유지한다.

**API 키만으로 계정의 무료 요금제를 확인하거나 비용 0원을 보장할 수는 없다.** Free Plan을 유지해야 한다. 이 기능이 계정을 유료로 전환하거나 결제를 등록하지는 않는다. Railway 운영비나 학교 서버의 이용 조건은 AI API 비용과 별개다.

Qwen3.6-27B는 현재 Groq의 Preview 모델이다. 제공 중단 시 모델 변경과 재검수가 필요하다. [지원 모델](https://console.groq.com/docs/models) · [사용 한도](https://console.groq.com/docs/rate-limits) · [결제 안내](https://console.groq.com/docs/billing-faqs)

## 전송 내용과 검증

- 현재 사용자의 조회 권한이 있는 영업건만 사용한다. 응답 후 권한과 버전을 다시 확인한다.
- 초기 요청 최대 2,500자, 최근 메모 3개 각각 최대 1,200자, 미완료 업무 최대 10개 각각 내용 최대 200자를 사용한다. 일부 기록은 길이 제한으로 생략될 수 있다.
- 별도 회사명·담당자명·전화·이메일 필드와 내부 식별자는 보내지 않는다. 자유 입력 문장에 있는 흔한 휴대전화·이메일 형식은 가린다. **완전한 익명화를 보장하지 않으므로 이 단계에서는 예시 정보로 시험한다.**
- 상담 문장은 지시사항이 아닌 입력 자료로 취급한다. 모델에 시스템 작업을 실행할 도구를 주지 않는다.
- Qwen3.6-27B는 Groq JSON Object Mode를 사용한다. 서버가 업무 종류·단계·문자열 길이·근거 문구 등을 추가 검사한다. JSON 형식이나 근거 문구 일치가 업무 판단의 정확성을 보장하지는 않는다.
- 날짜의 일치하는 근거가 없으면 날짜를 비운다. ‘내일’, ‘다음 주’ 같은 상대 날짜는 이 구현에서 직원이 확인한다.
- 승인 시 기록된 모델·생성 시각의 서명을 확인한다. 승인 이력에는 사용한 모델과 생성 시각을 남기고 서명값 자체는 남기지 않는다.
- 요청 중 입력을 수정하거나 화면을 이동하면 늦은 AI 응답이 입력을 덮어쓰지 않는다.

## 개발 검수

```powershell
node --test apps/api/test/ai-suggestions.test.mjs
pnpm check
```

AI 테스트는 가짜 응답과 임시 DB를 사용하며 실제 Groq 서버를 호출하지 않는다. 설정 미완료, 접근 권한, HTTP 인증·출처·빈도 제한, 잘못된 형식, 날짜 근거, 응답 중 기록 변경, 승인 전 무변경, 출처 위조 차단과 승인 재시도를 검사한다.

2026-09-14 확인: 신규 AI 검사 20개 통과. 기존 검사와 타입 검사를 통과했고 웹 빌드를 완료했다. 임시 DB의 브라우저에서 제안 자동 채움, 한도 오류 후 수정한 입력 유지, 확인란 선택 후 승인 저장과 단계·업무 반영을 확인했다. 브라우저 검수의 AI 응답도 가짜 응답이며 실제 모델 정확도를 검증한 결과는 아니다.
