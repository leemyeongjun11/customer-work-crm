# 업무 완료 후 안내와 같은 요청 연결

갱신: 2026-09-13. [PR #7](https://github.com/leemyeongjun11/customer-work-crm/pull/7)을 통해 `staging`에 반영했다. 별도 시연 화면이 아니라 실제 `/live` CRM에서 사용하는 기능이다. 현재는 **규칙과 직원의 확인으로 작동하며 실제 AI 모델을 호출하지 않는다.**

## 완료 뒤 무엇을 해야 하는지 안내

상담 메모를 저장하거나 첫 연락을 완료한 경우, 또는 등록한 업무를 완료한 경우 ‘다음 진행 정하기’를 연다. 연락 시도만 기록한 경우는 해당하지 않는다. 안내를 닫아도 미결정 상태를 서버에 보관하며 오늘 할 일과 고객 상세에서 다시 이어갈 수 있다. 기능 도입 전에 끝낸 과거 업무에 안내를 소급 생성하지는 않는다.

1. 직원이 고객의 실제 상황을 선택한다. 예: 답변 대기, 수정 요청, 조건 협의, 계약 확정, 서비스 진행, 완료·취소.
2. 화면이 해당 상황에 맞는 영업 단계와 다음 업무의 등록안을 제시한다.
3. 직원이 업무 내용과 날짜를 수정하고 기존 미완료 업무도 확인한다. 이미 필요한 업무가 있으면 새 업무 추가를 해제하고 유지할 수 있다.
4. 확인란을 선택하고 **승인하고 업무에 반영**을 누르면 단계와 다음 업무를 함께 저장한다.

예를 들어 ‘견적서 작성·전달’을 완료하고 ‘고객 답변을 기다리고 있어요’를 선택하면 ‘제안·협의’ 단계와 ‘견적 답변 확인’ 업무가 제시된다. 완료 버튼만으로 단계가 바뀌는 것은 아니다. 계약 후 수정 견적처럼 이미 더 진행된 단계에서는 기본 제안이 이전 단계로 되돌리지 않으며 직원이 직접 변경할 수 있다.

처리 날짜를 모르면 비워 두고 ‘기한 확인 필요’로 관리한다. 서비스 완료나 요청 취소를 선택하면 남아 있는 업무가 활동 목록에서 제외되는 영향을 확인한 뒤 승인한다. 기록을 삭제하지는 않는다.

## 다른 사람이 연락했지만 같은 실제 요청인 경우

예: 같은 회사의 A가 2층 에어컨 점검을 신청한 뒤, 같은 부서의 B도 동일한 점검을 요청한 상황이다.

1. B의 상담 결과를 저장하면 접근 가능한 같은 업체의 진행 중인 영업건을 후보로 보여 준다.
2. **이 건과 비교**에서 두 요청의 연락처·요청 내용·최근 메모·업무를 비교한다.
3. 부서·장소·실제 요청까지 동일한지 직원이 확인한다. 2층 에어컨과 4층 실외기처럼 다른 요청이면 **별도 요청으로 유지**한다.
4. 같은 요청이면 추가 건에서 가져올 미완료 업무를 선택하고, 같은 요청으로 판단한 이유와 확인란을 작성해 연결한다.
5. 기존 건의 담당자가 한 영업건에서 이어서 관리한다. 연결 후 다음 진행도 결정한다.

기존 건의 업무는 유지한다. 추가 건에서 선택하지 않은 미완료 업무는 관리 제외 기록으로 남긴다. 연락처·상담 메모·변경 이력·완료 기록을 보존하며, 연결된 고객 담당자 이름으로 검색해도 대표 영업건을 찾는다. 기존의 추가 건 주소로 접근하면 권한을 확인한 뒤 연결된 영업건을 연다.

## 현재 판단 범위

- 후보는 업체명에서 공백과 영문 대소문자를 정리해 일치하는 접근 가능한 진행 건을 찾는다. 회사명 유사도나 상담 의미를 AI로 분석하지 않는다.
- 조회 권한이 없는 건은 비교·연결할 수 없으며, 연결 후에는 기존 건 담당자가 추가 연락처·기록을 함께 관리한다.
- 직원 승인 없이 단계 변경·업무 생성·요청 연결을 확정하지 않는다.
- 실제 전화·문자·견적서 발송, 통화 녹음과 자동 요약은 수행하지 않는다.
- [AI 업무 정리 시연](06m-ai-workflow-demo.md)의 준비된 결과와 달리 이 화면의 승인 내용은 실제 시험 DB에 저장된다.

## 검수 기록

위 결과는 기능·기술 검수이며 실제 기업에서의 고객 대응 누락 감소나 AI 정확도를 측정한 결과는 아니다.
